# Apple 新邮件通知

在「设置与设备 → 新邮件通知」中开启后，应用会向系统请求普通提醒和声音权限。默认通知只显示「收到新邮件，点按查看」，用户可另行允许显示发件人与主题。「测试系统通知」仅验证系统提醒，不会发送邮件。

## 已实现的范围

- 使用 Apple `UserNotifications`，适用于 macOS 13、iOS/iPadOS 16、watchOS 9 及以上版本。
- Mac 应用仍运行、窗口可用时每 30 秒检查；iPhone/iPad 前台每 30 秒、Apple Watch 前台每 60 秒检查。iOS/watchOS 离开前台、窗口销毁、退出或撤销配对会取消任务。在 Mac 隐藏窗口或切换应用时可继续检查，关闭最后窗口后不保证继续运行。
- 使用经过配对认证的 `POST /api/native/v1/events`，与 Windows 共用服务端事件查询和游标规则。服务器只返回最近一天、目前仍未读且位于收件箱的事件，每页最多 25 条。不会依据本地邮件时间或收件箱首页猜测新邮件。
- 游标按服务器和已认证的用户隔离，保存在本机应用私有偏好中。首次检查、切换用户、服务端事件序列重置、退出后重新配对和重新启用通知时安静建立基线。正常重启继续先前游标，分页处理应用关闭期间保留的事件。数据始终使用十进制字符串比较，不经过浮点数转换。
- 检查事件关联的邮箱仍属于当前连接账户后显示；旧邮件标为未读、归档或重复请求不会凭空产生新事件。临时错误不弹出重复警告；401 会结束会话。
- 通知载荷只含服务器、邮箱 ID、邮件路由和会话代次，不含凭据或正文。未开启预览时，通知不含发件人与主题。
- 点击邮件通知须经过现有配对、服务器匹配和账户连接检查，再走应用内邮件链接路由。退出或设备撤销会移除对应服务器待发和已展示的通知，并取消未完成请求的结果。

## 边界与仍需真实设备验证的项目

这不是 APNs 推送，没有添加未经配置的推送 entitlement、后台持续执行或后台刷新承诺。iPhone、iPad、Watch 在后台及应用退出后不能依靠此功能收取新邮件提醒。系统权限、专注模式等可能影响通知的展示与声音。

新邮件识别和分页与 Windows 使用同一服务端逻辑；系统调度仍遵循各平台限制。超过一天的未处理事件可能已过事件查询窗口，应用未运行时不会自动拉取；它们仍可在邮箱中查看。旧服务器或不支持该事件流的部署返回 `NOT_FOUND` 时，设置明确显示通知功能不可用，普通收件箱刷新保持可用。

自动测试覆盖首次安静基线、事件去重、25 条以上分页、服务端/用户隔离、持久化重启、大于 JavaScript 安全整数的精确游标、过滤后的水位前移、无效/倒退页面、服务端序列重置以及认证 POST 契约。命令：

```sh
swift test --package-path native/apple --filter MailEventTrackerTests
```

真实系统验收：授权后触发测试通知；关闭权限后确认停止显示；在专用测试邮箱收到新邮件、点击通知打开对应会话；多账户及切换服务器验证隔离；开启/关闭预览检查锁屏；进入后台和返回前台检查任务停止/恢复；设备撤销后确认通知及配对失效。未经实际执行的系统弹窗、声音、锁屏、后台和真机检查不能仅凭单元测试记为通过。

API 依据：[请求通知权限](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications)、[处理通知与用户交互](https://developer.apple.com/documentation/usernotifications/handling-notifications-and-notification-related-actions)。
